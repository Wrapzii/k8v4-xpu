2026-11-05T20:13Z qsa: gather pooled blocks and call the XPU score and top-k
- The forward gathers one pooled row per logical block through the block table, including a swapped table and a block table whose entry covers two kernel pages.
- On XPU that matrix is scored with qsa_score and ranked with qsa_topk. CPU scoring stays on the fp64 reference, one query at a time, so the existing dense-match tests stay bit-exact.
- A query still inside the block budget does not score and stays on dense K8/V4. One block past the budget is scored, because forcing the own block back in can restore a full causal set.
- Projection, norms, pooling, and RoPE stay fp64 on CPU. Off CPU they run in fp32.
- CPU tests in an ephemeral container, no GPU, image unchanged: 26 tests OK, 2 device tests skipped. No production kernel, container, or image changes.

2026-11-05T20:21Z qsa: load indexer norms as zero-centered deltas
- Training stores q_norm, k_norm, and k_block_norm as 1+weight deltas (zeros at init). conversion/qwen.py adds 1 when it writes GGUF. ggml build_norm multiplies by that stored vector and does not add 1 again. The in-memory bank keeps the real multiplier, and load_bank_file adds 1 unless safetensors metadata says norm_storage=multiplier.
- A stored zero therefore loads as ones, which is an identity RMSNorm. The training export key layers.{i}.self_attn._qsa_indexer.* is accepted. The training score scale 1/sqrt(128) is positive and shared, so it does not change top-k order. The fast path still does not apply it.
- CPU test, ephemeral container, no GPU: test_qsa_ref 11 tests OK. No production kernel, container, or image changes.
