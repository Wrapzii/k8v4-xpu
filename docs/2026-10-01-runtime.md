# October 1 runtime update

The production server recovered after a VM reboot cleared a new Intel GPU memory CAT fault. Qwen's vision tower is enabled; an OpenAI chat request containing a 64×64 red PNG returned `red`. The server retains TP2, MTP6, four active sequences, and a 262,144-token request window. Startup reported 830,415 tokens of shared KV capacity, not four fully occupied context windows.

## Hermes thinking controls

Qwen thinking is now enabled in the local Hermes profile and the server's Wrapzii profile. Low is the default for this model. The shared provider configurations carry the same setting for other profiles that select it. Existing defaults for other models are preserved.

```yaml
agent:
  reasoning_overrides:
    Qwen3.8-27B-GPTQ-Int4-baked-v2-embed-int8: low
```

Remove the provider's fixed `extra_body.chat_template_kwargs.enable_thinking: false`. Do not pin `chat_template_kwargs.reasoning_effort`: Hermes sends the selected effort as the top-level `reasoning_effort` field, and this installed vLLM version passes it to the template and enables thinking automatically. The deployed template defaults to low when no effort is supplied.

Use Hermes' effort selector, or `/reasoning low` and `/reasoning medium`, to select the desired effort for a conversation. These two settings were checked through Hermes' actual request builder on both machines. Small live requests for both levels produced reasoning and the correct arithmetic answer. These were functional checks, not performance measurements. Existing running agents may retain old provider overrides until a native graceful restart or a model reload; let active work drain rather than killing build processes.

## Boot settings and slowdown investigation

An obsolete `b60-powerclamp.service` ran after model startup and reset both GPUs to a 100 W burst limit and 1,800 MHz maximum frequency. It is now disabled. The existing `ai01-gpu-tune.service` restored and retains the previously established 180 W / 2,400 MHz settings. No model restart was required for this correction.

Live service logs also showed overlapping requests and substantial host-memory paging during concurrent Rust builds: the guest has approximately 12 GiB RAM, about 1 GiB available in the observed sample, and roughly 14 GiB swap occupied. `vmstat` confirmed active paging rather than merely stale swap allocation. Ten-second aggregate vLLM log rates are not comparable to the earlier isolated, per-request benchmark curve.

The logs do not isolate vision's performance overhead. No new performance benchmark or matched vision-on/vision-off comparison was run. Published coding performance results remain the earlier text-only measurements.

## Runtime cleanup

Hermes' deleted virtual environment was restored from the repository's pinned dependencies. The cause of its deletion remains unconfirmed. The audited disk watchdog now preserves worktrees and sources, defers cleanup during active Forge jobs, and only removes marked, stale generated Cargo targets that are not in use, plus old terminal output. Preserve virtual environments, installed runtimes, model weights, serving overlays, native libraries, and credentials when cleaning disk space.
