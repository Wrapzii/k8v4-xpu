# QSA integration status

Both `K8V4_QSA_ADEQUATE_WIDTH_GRAPH=1` and `K8V4_QSA_PREFILL_PREFIX_SKIP=1` are experimental opt-ins, disabled by default. CPU tests and synthetic component measurements do not qualify either change for serving. The prefix bypass applies only inside exact-tiled prefill to a whole request-local tile whose complete-block counts are within the selection budget; mixed over-budget tiles use the regular path.

The synthetic component experiment compared the complete 128 x 2052 packed ID tensor with the native packer (zero mismatches) and direct attention (bit-identical); its 128 x 512 score input ensured the native-packer branch was exercised. All pooled blocks were valid in that experiment. The result excludes projection, gather, cache writes, and serving. The bypass emits the full causal prefix without testing invalid pool entries or non-finite scores. The torch fallback also explicitly selects the full prefix for within-budget rows, but native-packer parity for invalid or non-finite inputs is **not established**; do not enable pending correctness and serving validation.

A historical 8K serving run at source commit `e46eb970fae94f9e81c9a92d1aa605e6bcc69068`, before either candidate, reported client time to first token of 17.003431 s for QSA and 8.868014 s for dense, each with 96 output tokens. The client observed 25 and 4 output events respectively; dense burst buffering compromises interpretation of TTFT as GPU prefill throughput and makes its apparent decode rate unreliable. Dense decode throughput is therefore unavailable, and no matched-quality claim is made. GPU0 faulted during cleanup before candidate testing, so there is no candidate serving result.
